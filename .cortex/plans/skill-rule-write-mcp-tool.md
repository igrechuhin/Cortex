## Goal

Add a `write_artifact` MCP tool (or extend `skill_pack`) that allows analysis agents
(`analyze-compact`, `post-prompt-hook`, `analyze.md` Step 9a/9c) to reliably write skill
JSON files and rule `.mdc` files via MCP — rather than telling them to use `manage_file`,
which is hard-coded to `.cortex/memory-bank/` and will reject any other path.

Simultaneously, update all three routing prompts that describe these operations so they
call the new/extended tool instead of the incorrect `manage_file`.

---

## Context

### Why this is broken today

The analysis pipeline's self-improvement loop is supposed to route findings to three
artifact types:

| Artifact | Location | Tool called by prompts |
|----------|----------|----------------------|
| Plans | `.cortex/plans/` | `plan(operation="create/register")` ✅ works |
| Skills | `src/cortex/resources/skills/<name>.json` | `manage_file(operation="write")` ❌ wrong tool |
| Rules | `.cortex/synapse/rules/<lang>/<slug>.mdc` | `manage_file(operation="write")` ❌ wrong tool |

`manage_file` resolves all paths against `memory_bank_dir` (`.cortex/memory-bank/`).
From `manage_file_helpers.py:246`:

```python
memory_bank_dir = get_cortex_path(root, CortexResourceType.MEMORY_BANK)
return _validate_file_path_impl(fs_manager, memory_bank_dir, file_name)
```

Any call to `manage_file(file_name="src/cortex/resources/skills/foo.json", operation="write")`
will be rejected. The path traversal guard (`..`, `/`) in `_validate_file_path_impl` will also
block absolute or rooted paths.

As a result, no skills and no rules have ever been auto-generated by the post-prompt hook or
the analyze pipeline, even when findings warranted them.

### What was already partially fixed

A previous session corrected the wrong path (`.cortex/resources/skills/` → `src/cortex/resources/skills/`)
in three prompts and added schema templates and tool invocation hints. However the referenced tool
(`manage_file`) still cannot reach those paths. The prompt fix is necessary but not sufficient.

### Paths that need to be writable

1. `src/cortex/resources/skills/<name>.json` — skill pack manifests
   - Schema: `SkillPackManifest` model in `src/cortex/tools/skill_pack/models.py`
   - Loaded at runtime by `_get_skills_dir()` in `src/cortex/tools/skill_pack/operations.py`
     (resolves via `Path(__file__).parent.parent.parent / "resources" / "skills"`)
   - Files are Python package resources (shipped inside the installed package)

2. `.cortex/synapse/rules/<general|python|...>/<slug>.mdc` — Synapse rules
   - Plain Markdown with YAML frontmatter
   - Loaded via Synapse rules index; no binary format

### Architecture decision: extend `skill_pack` vs add `write_artifact`

**Option A — Add `write_artifact` MCP tool** (new tool, generic allowlisted write)

Pros: clean separation; `manage_file` stays memory-bank-only; easy to expand allowlist.
Cons: +1 to tool count (currently targeting ≤40 registered tools).

**Option B — Extend `skill_pack` with `operation="write"`**

Pros: no new tool slot consumed; skill writes are already semantically in `skill_pack`'s domain.
Cons: mixing read/discover operations with write in same tool; rules write is out of scope for `skill_pack`.

**Option C — Add `write_artifact` but internalize it (not registered as MCP tool)**

Makes it callable from Python (e.g. from within other MCP handlers) but not from agent prompts.
Does not solve the problem — agents need to call it via MCP.

**Chosen approach: Option A — `write_artifact` MCP tool** with a static path allowlist.

Rationale:

- Plans already use a dedicated `plan()` tool; rules/skills deserve the same clarity.
- A static allowlist (`src/cortex/resources/skills/`, `.cortex/synapse/rules/`) makes
  the security boundary explicit and auditable.
- Tool count impact: +1. The existing `skill_pack` tool remains read-only (discover/load).
  If tool budget is tight, `write_artifact` can later be folded into `skill_pack` as
  `operation="write_skill"` and `operation="write_rule"`.

## Implementation Steps

### Step 1: Create `write_artifact` MCP tool

**File**: `src/cortex/tools/artifacts/write_artifact.py` (new file)

1. Define `ArtifactType` enum: `SKILL = "skill"`, `RULE = "rule"`.
2. Define allowlist function `_resolve_artifact_path(artifact_type, name, project_root)`:
   - `SKILL`: resolves to `src/cortex/resources/skills/{name}.json`
     — uses `Path(__file__).resolve().parent.parent.parent / "resources" / "skills" / f"{name}.json"`
     (same logic as `_get_skills_dir()` in `skill_pack/operations.py`)
   - `RULE`: resolves to `project_root / ".cortex" / "synapse" / "rules" / name`
     where `name` must be a relative path like `general/my-rule.mdc` or `python/my-rule.mdc`
   - Reject any `name` containing `..` or absolute path components.
3. Validate content:
   - For `SKILL`: parse as JSON, validate against `SkillPackManifest`. Return error if invalid.
   - For `RULE`: require non-empty content and YAML frontmatter block (starts with `---`).
     Extract and validate that `description` field is present in frontmatter.
4. Write atomically: write to a `.tmp` file then rename (avoids partial writes).
5. Return JSON: `{"status": "success", "artifact_type": ..., "path": ..., "name": ...}` or error.
6. Register as MCP tool with `@mcp.tool(annotations=safe_write_annotations("Write Skill or Rule Artifact"))`.

**Signature**:

```python
async def write_artifact(
    artifact_type: ArtifactType,
    name: str,
    content: str,
    ctx: MCPContext | None = None,
) -> str:
```

### Step 5: Write tests

**File**: `tests/tools/test_write_artifact.py` (new file)

Use the AAA pattern. Target ≥95% line coverage for `write_artifact.py`.

Tests to include:

1. `test_write_skill_creates_valid_json_file` — write a valid `SkillPackManifest` JSON; assert file exists and is parseable by `SkillPackManifest.model_validate_json`.
2. `test_write_skill_rejects_invalid_json` — content that is not valid JSON; assert `status == "error"`.
3. `test_write_skill_rejects_missing_required_fields` — JSON missing `name`/`tools`; assert `status == "error"`.
4. `test_write_rule_creates_mdc_file` — write a valid `.mdc` with frontmatter; assert file exists and content matches.

## Success Criteria

1. `write_artifact(artifact_type="skill", name="foo", content=<valid_json>)` creates
   `src/cortex/resources/skills/foo.json` and the file is immediately loadable via
   `skill_pack(operation="load", pack_name="foo")`.
2. `write_artifact(artifact_type="rule", name="general/foo.mdc", content=<valid_mdc>)`
   creates `.cortex/synapse/rules/general/foo.mdc`.
3. Path traversal attempts (`../../`, absolute paths) return `status == "error"` with a
   clear message — no file is written.
4. Invalid content (bad JSON for skills; missing frontmatter for rules) returns
   `status == "error"` — no file is written.
5. All three routing prompts (`analyze.md`, `analyze-compact.md`, `post-prompt-hook.md`)
   reference `write_artifact` for skills and rules; no `manage_file` references remain
   in skill/rule routing context.
6. 10 tests pass, ≥95% coverage on `write_artifact.py`.
7. Tool count ≤40 after registration.
